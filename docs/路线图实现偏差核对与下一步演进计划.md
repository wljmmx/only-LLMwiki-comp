**技术要点**：
1. 事件总线选型：单机用 `asyncio.Queue`，多机升级 Redis pubsub（与现有 CollabHub 一致）
2. 增量推送：graph_changed 事件携带 `{action, entity_id, entity_type, changed_fields}`，前端增量更新而非全量刷新
3. graph→wiki 重编译：订阅 graph_event_bus，BFS 沿 backlink 链计算影响集合（深度≤2，上限 20 页），乐观锁防并发重编译，TTL 防僵尸锁；与批量 `detect_graph_drift` 互补最终一致
4. 可视化性能：Vue Flow 已限制 200 节点，路径分析时高亮子图，避免全图重渲染
5. 目录树：复用 heading_tree 骨架 + index.md 分组，前端用 NTree 组件渲染

**KNOW-13 实现说明**（2026-08-03）：
- 新增 `backend/app/realtime/graph_wiki_sync.py`：`GraphWikiSync` 协调器，app lifespan 启动时 `start()`、停止时 `stop()`
- 事件过滤：仅处理实体级变更（upsert/delete/merge），关系级变更交给批量 `detect_graph_drift` 兜底，避免事件风暴
- 影响集合：种子=实体名直接匹配 slug + backlink 来源页；BFS 沿 backlink 扩展（深度≤2），单次上限 20 页防雪崩
- 重编译：从页面 frontmatter `sources` 提取 doc_id，调用 `wiki_compiler.recompile_section`，成功后 `clear_stale`，失败保留 stale 标记
- 乐观锁：`_in_progress` 字典 + 300s TTL，防止并发重编译同一页面与僵尸锁
